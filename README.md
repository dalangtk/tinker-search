# tinker搜索

Windows 本地文件**即时搜索**工具。基于 **Tauri 2 + Rust + Vue 3**，直接解析 NTFS 主文件表（MFT）建立全盘索引，输入即搜，毫秒级返回结果。

索引与查询全部由自研 Rust 内核 [`sscore`](sscore) 完成，不依赖任何第三方搜索引擎、服务或 DLL。

实测一台 i9-12900H / 32 GB / 双 NVMe 的机器、3 个 NTFS 卷 1.4 TB 共 **496 万条**：首次建库 **28.8 秒**（缓存热时 8.8 秒），常驻内存 **218 MB**，查询中位 **15 ms**，实时同步 CPU 占用 **0.18%**。详见 [性能实测](#性能实测) 与 [索引内核 sscore](#索引内核-sscore)。

- **版本**：1.0.0
- **平台**：Windows 10 / 11（x64，NTFS）
- **安装包**：`tinker搜索_1.0.0_x64-setup.exe`（约 1.9 MB）
- **协议**：[Apache-2.0](LICENSE)

## 功能特性

### 搜索

- **三种模式**：通配符（默认）、PCRE2 正则、类 SQL 查询，随时切换，无需重建索引
- **中文友好**：拼音全拼、首字母（`wj` → 文件）、拼音完整匹配，全角半角互通
- **组合条件**：空格表示「且」，`|` 表示「或」；通配符支持 `*`、`?`
- **范围限定**：可把搜索限定在某个磁盘、某个目录或侧栏选中的分类内
- **分页加载**：命中几十万条也不卡，滚动续取
- **搜索历史**：输入框为空时下拉最近 9 条，可单条删除或清空

### 浏览与筛选

- **首页概览**：磁盘容量条、桌面内容、各盘根目录，点目录名即可就地浏览
- **文件夹下钻**：结果里双击文件夹即可进入，进入后按「子文件夹 → 子文件 → 更深层内容」三组排序
- **面包屑地址栏**：多级路径逐级可点，任意一级都能一键回退；`Esc` 逐级返回上一级
- **侧栏分类**：常用位置（主目录 / 桌面 / 下载 / 文档 / 图片 / 音乐 / 视频）、文件类型（文件夹 / 快捷方式 / 程序 / 音频 / 视频 / 图片 / 文档 / 办公 / 压缩包 / 代码）、磁盘
- **筛选逻辑**：同类之间是「或」，跨类之间是「且」；已选条件在搜索栏下方以标签显示，可单独取消

### 结果操作

- **三种视图**：详情列表、紧凑列表、图标网格，网格图标大小可在设置中调（100–168 px）
- **排序**：相关度 / 文件名 / 文件夹 / 大小 / 修改时间 / 文件类型 / 路径 / 扩展名 / 创建时间 / 访问时间，点列头切换升降序，选择结果持久化
- **多选**：`Ctrl + 点击` 多选、`Shift + 点击` 连选，可批量复制、复制路径、删除到回收站
- **预览面板**：图片缩略、文本、Markdown 渲染、代码高亮，以及完整文件属性
- **单文件操作**：打开、资源管理器定位、重命名、查看属性、复制路径
- **删除可恢复**：只删到回收站，不做不可逆删除

### 系统集成

- **全局呼出**：默认双击 `Ctrl` 把窗口还原并置前，可在设置里录制任意组合键，热更新无需重启
- **托盘常驻**：关闭主窗口只是隐藏，托盘菜单可显示窗口 / 打开设置 / 保存索引 / 退出
- **单实例**：重复启动只会唤起已有窗口
- **URL 协议**：`tinker://` 链接从浏览器、快捷方式或其他程序唤起搜索
- **URL 协议安全边界**：协议以管理员身份运行，因此能做的事被限死在「搜索与界面设置」，`run=` 打开可执行文件 / 脚本类文件一律硬拒
- **窗口行为**：可选窗口置顶、失焦自动隐藏（像启动器一样点别处就收起）

### 界面

- **六套皮肤**：靛蓝（default）、暗夜、樱花、薄荷、赛博、玻璃

## 性能实测

下面每个数字都来自仓库内的 `sscore` 命令行（`mft` / `bench` / `watch`），不是估算值，可在同配置机器上一条命令复现。

### 测试环境

| 项目 | 配置 |
| --- | --- |
| CPU | Intel Core i9-12900H，14 核 20 线程 |
| 内存 | 32 GB |
| 磁盘 | 两块 NVMe SSD（1 TB + 512 GB） |
| 系统 | Windows 11 x64，NTFS |
| 索引范围 | 3 个 NTFS 卷，合计 1.4 TB，已用 1.09 TB |
| 索引条目 | 约 496 万条（目录 96.7 万，文件 399.4 万） |

### 建库：496 万条，首次 28.8 秒

| 卷 | 条目数 | 枚举 $MFT | 装配列式索引 | 落盘 | 合计 | 内存 |
| --- | --- | --- | --- | --- | --- | --- |
| C: | 2,552,935 | 10.22 s | 0.39 s | 0.08 s | 10.68 s | 115.5 MB |
| D: | 733,320 | 4.28 s | 0.07 s | 0.01 s | 4.36 s | 26.3 MB |
| E: | 1,678,171 | 13.49 s | 0.19 s | 0.05 s | 13.73 s | 76.5 MB |
| **合计** | **4,964,426** | **27.99 s** | **0.64 s** | **0.14 s** | **28.77 s** | **218.3 MB** |

- 平均 **17.2 万条/秒**。同样的 496 万条在系统缓存热的时候重建只要 **8.8 秒**（约 56 万条/秒）。
- 表中「合计」是逐卷「枚举 + 装配 + 落盘」的累加；应用内还会把这些卷合并成单库并挂上 USN 同步，量级相同。
- 耗时几乎全在枚举（97%），装配 + 落盘合计 0.78 秒——索引结构本身只扫一遍，没有二次排序、没有逐文件 `stat`。
- 不遍历目录、不读文件内容：只取卷上的元数据，所以 10 GB 的镜像文件和 10 KB 的文本在建库成本上一视同仁。
- 建库一次性成本，之后每次启动是加载索引文件（219 MB，见下），不是重新扫描。

同机对照（范围不同，只比单条成本）：用传统目录遍历枚举 `C:\Windows` 子树，39.5 万条花了 58.2 秒，约 **0.68 万条/秒**；MFT 枚举是 **17.2 万条/秒**，单条差 25 倍。条目越多、目录越深，差距越大。

```bash
./target/release/sscore.exe walk "C:\Windows" --db w.idx   # 0.68 万条/秒
./target/release/sscore.exe mft C --db c.idx               # 17.2 万条/秒
```

### 查询：496 万条中位 15 ms

200 个从索引里随机抽的真实文件名片段（2–6 字）× 3 轮，共 600 次查询：

| 指标 | 数值 |
| --- | --- |
| 中位 | 15.09 ms |
| p95 | 28.36 ms |
| 平均 | 16.86 ms |
| 最快 / 最慢 | 9.37 ms / 40.97 ms |
| 平均命中 | 39.7 条/次 |
| 名字池扫描吞吐 | 7.9 GB/s（119 MB 名字池全扫约 15 ms） |

输入过程中每敲一个字就是一次全库扫描，仍在下一次按键之前返回——这是「输入即出结果」的前提。

### 实时同步：CPU 占用 0.18%，新文件 250 ms 内可搜

让同步线程挂着一个 255 万条的索引跑 22 秒（250 ms 一轮，共 86 轮），期间创建 420 个文件、删除 300 个：

| 指标 | 数值 |
| --- | --- |
| 处理事件 | 1,809 条（增 557 / 删 137 / 改 32 / FRN 复用复活 134） |
| 同步累计耗时 | 39.4 ms / 22 s |
| 同步占用率 | **0.179%**（单轮均值 458 µs） |
| 空闲轮次 | 30–80 µs（日志没有新记录就立刻返回） |
| 新文件可见延迟 | ≤ 250 ms（一轮轮询内） |
| 同步期间的查询 | 中位 4.74 ms，p95 5.91 ms（不受写入影响） |

也就是说，索引在后台自动保鲜，代价基本可以忽略；同步是增量的，改一个文件不会重建整库。

### 内存与磁盘

| 项目 | 数值 |
| --- | --- |
| 常驻内存 | 218.5 MB / 496 万条 = **46.2 字节/条** |
| 索引文件 | 约 219 MB（46.3 字节/条），单文件，可直接拷贝备份 |
| 启动加载 | 166 ms（218 MB 顺序读） |
| 名字池 | 119.1 MB（全路径不落库，靠父指针现场拼） |

作为参照：496 万条如果为每条存一份完整路径字符串，单是路径就要数百 MB，而 `sscore` 只存名字 + 父指针，整个索引 200 多 MB 装得下。

## 索引内核 sscore

`sscore` 是本项目的核心，也是「为什么快」的答案：一个不依赖第三方引擎的 Rust 索引内核，约 3,900 行，依赖只有 `rayon`（并行）和 `memchr`（字节扫描）两个库。整个内核在应用进程内运行，没有服务、没有 DLL、没有 IPC。

```
USN 日志 ─┐
          ├─▶ 增量增删改 ─▶ 索引（列式内存）
$MFT ─────┴─▶ 全量枚举 ──▶ assemble ──▶ 索引 ──▶ 并行扫描 ──▶ 评分 / 分页
```

### 枚举：向 NTFS 要元数据，而不是遍历目录

- 打开 `\\.\C:` 卷句柄，用 `FSCTL_ENUM_USN_DATA` 一次性把整卷记录拉回来；每条记录自带 `FileReferenceNumber`、父引用、文件名和属性位——正好是索引需要的全部字段。
- 不解析 MFT 记录结构、不递归 `FindFirstFile`。目录树在内存里用父指针重建，所以成本与目录层数、文件大小无关，只与条目数有关。
- 枚举和装配都是单线程顺序处理（瓶颈在卷的元数据读取），17.2 万条/秒是单核跑出来的；多核留给查询。
- 非管理员场景退化为目录遍历（`sscore walk`），能建库但没有 FRN 列，实时同步不可用。

### 存储：列式 + 父指针，46 字节一条

- 记录拆成 6 个并列数组：`parent`(u32) / `name_off`(u32) / `name_len`(u16) / `vol`(u16) / `flags`(u8) / `frn`(u64)，名字统一进一段连续字节池。
- **不存全路径**，要路径时按父指针现场拼（`path_of`），路径长度不影响内存。
- 大小、创建/修改时间不进索引：排序或过滤真正用到时才 `stat` 一次并缓存，用完即弃。
- 落盘是自定义紧凑格式，加载就是把几段数组一次读进内存——219 MB / 166 ms，没有 B+ 树、没有页缓存预热、没有 WAL 回放。

### 查询：全库并行子串扫描

- 索引按 3.2 万条切块分给 rayon 线程池，每块用 `memchr` 直接跳到候选首字节，再做大小写/全角/拼音比较。
- 每块只保留最有希望的 1024 条，合并后再排序截断——全命中时也不会把内存打爆。
- 评分规则简单可预测：完全相等 +900、前缀 +600、词边界 +300，名字越短越靠前，目录略降权。
- 分页只在结果 id 序列上切片，翻到第 20 页也不重新扫描。

### 同步：卷级 USN，增量而非重建

- 一个卷一个日志句柄，订阅时用 `REASON_MASK` 只要「创建 / 删除 / 改名」——写文件产生的 `DATA_EXTEND` 之类在核内就被过滤掉，不会进到用户态。
- 断点（journal id + USN 位置）随索引一起落盘，重启后从断点续读，进程没运行期间的变更也能补上。
- 删除标墓碑、FRN 被系统复用时会识别并复活对应记录，索引不会因为反复增删而膨胀。

## 使用说明

### 三种搜索模式

搜索框左侧的下拉可切换模式，占位提示会随模式变化给出语法示例。

#### 通配符（默认，类型 0）

```
报告                 # 包含「报告」
*.pdf                # 后缀过滤
2026-*-周报.docx     # * 任意长度
IMG_????.jpg         # ? 单个字符
bg 2026              # 空格 = 且，同时包含 bg 和 2026
bg|报告              # | = 或
wj                   # 拼音首字母也能命中「文件」
```

#### 正则（类型 1）

标准 PCRE2 语法：

```
^[0-9]{4}-报告.*\.docx$
^(IMG|DSC)_\d{4}\.jpe?g$
```

#### SQL（类型 2）

索引被视作一张名为 `alltable` 的表，结果以表格呈现，双击行同样能打开文件。

```sql
SELECT * FROM alltable WHERE FName LIKE '%模板%' AND Ext = 'pdf'

SELECT FName, Size, Mtime FROM alltable
WHERE Size > '100M' AND Mtime > '2026-01-01'
ORDER BY Size DESC LIMIT 50

SELECT Ext, COUNT(*) FROM alltable GROUP BY Ext ORDER BY COUNT(*) DESC LIMIT 20

SELECT SUM(Size) FROM alltable WHERE Ext = 'mp4'
```

- **字段**：`Path` / `FName`(`Name`) / `Ext` / `Size` / `Mtime` / `Ctime` / `Atime` / `Dir`(`IsDir`) / `Drive` / `Type`，也认中文别名（路径、文件名、后缀、大小、修改时间、创建时间、访问时间、文件夹、磁盘、类型）
- **条件**：`=` `!=` `<>` `>` `>=` `<` `<=` `LIKE` `IN` `BETWEEN` `AND` `OR` `NOT` `()`
- **聚合与分组**：`COUNT(*)`、`SUM(Size)`、`GROUP BY`、`ORDER BY`、`LIMIT`、`DISTINCT`
- **性能保护**：索引里不存大小与时间，涉及 `Size` / `*time` 的条件需要对候选文件 `stat`。候选超过 40 万条时会直接报错并提示加条件，而不是让界面卡死——先写索引列（路径 / 名字 / 后缀 / 盘 / 类型）把候选压下来，再用大小时间过滤。

### 侧栏筛选

| 分组 | 内容 |
| --- | --- |
| 常用位置 | 主目录、桌面、下载、文档、图片、音乐、视频（来自 `SHGetKnownFolderPath`） |
| 文件类型 | 文件夹、快捷方式、程序、音频、视频、图片、文档、办公、压缩包、代码 |
| 磁盘 | 各本地卷及剩余空间；未收录进索引的盘会标注「未索引」 |

同类多选是「或」，跨类多选是「且」。例如：选中「桌面」+「文档」两个位置 + 「图片」类型 = 这两个位置里的图片。已选条件以标签显示在搜索栏下方，右上角「清除」一键复位。

`全部` 表示不限类型；选「文件夹」时只保留目录，并且其他后缀条件不再生效。反过来，选中任一具体类型（文档、图片…）后目录本身不会出现在结果里。

### 文件夹浏览与地址栏

- 首页点击磁盘或目录名即可就地浏览
- 结果区双击文件夹进入其内部，空关键词时按目录内容列表展示
- 进入目录后，排序固定为：**子文件夹 → 子文件 → 更深层内容**，每组内部保持你选择的列排序
- 顶部出现面包屑：`C: › Users › woshi`，每一级可点击回退，末级为当前目录并显示项数，最左侧按钮返回首页
- `Esc` 在无关键词、无菜单时返回上一级目录

| `Delete` | 删除到回收站（多选时批量删除） |
| `Ctrl + C` | 复制路径（多选时复制所有选中路径） |
| `F5` | 重新搜索 |
| `Esc` | 关右键菜单 → 清空关键词 → 返回上级目录 → 隐藏窗口 |

全局呼出键在「设置 → 外观与窗口」里配置：先用「启用全局呼出快捷键」总开关打开，再选择预设或点「自定义」录制（录制时按 `Esc` 取消）。支持两类绑定：

- **双击修饰键**：`DoubleCtrl`、`DoubleAlt`、`DoubleShift`、`DoubleWin`
- **组合键**：`Ctrl+Alt+S`、`Ctrl+Shift+F`、`Alt+Space`、`Win+Q` 等，必须含至少一个修饰键（避免裸键被全系统拦下）

修改后立即生效，不需要重启。若设置里提示「键盘钩子未安装，可能被安全软件拦截」，把程序加入安全软件白名单即可。

## URL 协议

在「设置 → 外观与窗口 → 注册 tinker:// 协议」打开开关后，可通过 `tinker://` 链接调用：

```text
tinker://new?q=报告&filter=文档
tinker://new?q=*.pdf&mode=wild&view=grid
tinker://search?q=项目&sort=修改时间&order=desc
tinker://new?q=2026&scope=D:\项目
tinker://new?q=报告&ms=["周报.docx","月报.docx"]
tinker://focus
tinker://new?settings=index
```

| 参数 | 说明 |
| --- | --- |
| `q` / `keyword` | 搜索关键词 |
| `ms` | 多重搜索链，值为 JSON 数组，元素可为字符串或 `{"q":"…","mode":"…"}` |
| `mode` | `wild` / `regex` / `sql`，或类型值 `0` / `1` / `2`，也可填自定义模式名 |
| `filter` / `cat` | 文件类型筛选，多个用 `、` 分隔，或传 JSON 数组 |
| `scope` | 搜索范围目录，传单个路径（候选多个时只取第一个） |
| `view` | `list` / `dense` / `grid` |
| `sort` / `order` | 排序字段与升降序 |
| `zoom` | 网格图标大小（100–168） |
| `skin` | 皮肤名：`default` / `dark` / `sakura` / `mint` / `cyber` / `glass` |
| `preview` | `1` / `0` 开关预览面板 |
| `settings` | 打开设置页：`search` / `index` / `appearance` / `about` |
| `reveal` / `props` | 定位到某路径 / 打开某路径的属性（需绝对路径） |
| `run` | 用系统程序打开某文件，非脚本类也要二次确认 |
| `addmode` / `delmode` | 新增 / 删除自定义模式（`mtype`、`tpl`、`mdesc`、`priv`），均需确认，模式上限 40 个 |
| `cleartags` | 清空多重搜索链与关键词 |
| `pinyinfull` / `pinyininitial` 等 | 匹配开关，取 `1` / `0` |

出于安全考虑，`run=` 打开可执行文件 / 脚本类文件（exe、bat、ps1、cmd 等）的请求会被直接拒绝，不弹确认框；其余可打开的文件也会先弹确认。

`win` / `save` / `hotkey` 三个参数已在解析层预留，当前版本尚未落到界面。

## 索引与权限

- **建立索引**需要管理员权限：读取 `$MFT` 以及启用 USN 实时同步都依赖它。
- **搜索、预览、打开、定位、复制、托盘、快捷键**本身不需要管理员权限，已有索引在普通权限下也能查询。
- 发布版在应用清单里声明了 `requireAdministrator`，安装后启动即为管理员，建库与实时同步直接可用；开发模式（`cargo run`）未提权时会提示以管理员身份重启。
- **实时同步**：通过 NTFS USN 日志增量跟随文件增删改，状态栏的「实时同步」即是它；大量改动会合并成批处理。
- **索引管理**（设置 → 索引管理）：查看索引条目数、内存占用、库版本、引擎状态与索引文件路径；勾选磁盘分区重建索引；维护排除目录。托盘菜单里的「保存索引」可手动落盘（正常退出也会自动保存）。
- **多盘与增量**：每个卷独立建索引，索引文件可复用；文件改动后无需全量重建。

调试技巧：

- 前端调试走 `?mock=1`，不依赖索引；`src/mock.ts` 提供假数据与假命令。
- 热键相关的自动化验证：debug 构建下设置环境变量 `TINKER_HOTKEY_TEST=1`，低层钩子会放行 `keybd_event` 注入的按键，可用脚本驱动「关闭 → 双击 Ctrl 唤出 → 最大化 → 外部最小化 → 还原」全流程。
- 索引内核的 `sscore` 是本地路径依赖（`../sscore`），改动后主程序重新编译即可生效。

### 实现要点

- **窗口显隐统一走 tao**：主窗口是 `decorations: false`，若只用原生 `SW_SHOW` 显示，tao 内部的 `VISIBLE` 标记仍为 false，后续 `maximize()` 会补一刀 `SW_HIDE`，表现就是「窗口连标题栏一起消失」。所以原生代码只负责立即还原最小化与突破前台锁，显隐交由 tao 并在主线程按序执行。
- **钩子回调里不做窗口操作**：`WH_KEYBOARD_LL` 回调必须快速返回，超时会被系统静默摘钩。回调只投递信号，窗口操作交给独立线程。
- **物理键码**：低层钩子报告左/右 Ctrl 为 `0xA2` / `0xA3`，不是通用 `VK_CONTROL(0x11)`，必须识别整族键码，否则真机上热键失效。
- **排序稳定性**：目录内三组排序用稳定排序实现，组内保持用户选择的列序。

## 常见问题

**Q：双击 `Ctrl` 没反应？**
A：先看「设置 → 外观与窗口」里快捷键下方的提示；若显示「键盘钩子未安装，可能被安全软件拦截」，把程序加入白名单。也可能是快捷键被改成了组合键，用「自定义」重录一次。

**Q：搜索结果一直是 0 条？**
A：确认目标磁盘已收录索引（侧栏磁盘项若标注「未索引」就不会有结果）。也可能筛选条件过窄——看搜索栏下方的类型标签，点「清除」复位。

**Q：为什么首次启动要等一会儿？**
A：在读 `$MFT` 建库，496 万条约 29 秒，只在第一次（或重建时）发生；之后启动是加载索引文件，约 0.2 秒。可以在设置里排除掉不需要索引的大目录来进一步缩短。

**Q：普通权限能用吗？**
A：能。搜索、打开、定位、删除、复制、托盘、快捷键都不需要管理员；只有建库和实时同步需要。

**Q：删除的文件去哪了？**
A：只进回收站，可随时还原。程序不做不可逆删除。

**Q：窗口关掉后程序还在运行？**
A：这是托盘常驻设计。托盘图标右键可「显示主窗口」或「退出」。

**Q：安装时提示「Windows 已保护你的电脑 / 未知发布者」？**
A：安装包未做代码签名，属于正常现象。点「更多信息 → 仍要运行」即可；也可以在正式分发前补一张签名证书。

## 已知限制

- 仅支持 Windows + NTFS；FAT32 / exFAT / 网络盘无法走 MFT，会退化为目录遍历，速度明显下降。
- 索引不存文件大小与时间，`Size` / 时间排序与过滤在首次使用时需要现场 `stat` 并缓存。
- SQL 模式涉及大小与时间条件时，候选超过 40 万条会拒绝执行并提示收窄条件。
- 实时同步依赖 USN 日志，非管理员运行时只能手动重扫。
- 别名、评分与加权规则在界面上留有入口，但当前索引内核不维护这类可写元数据，操作会明确报错（「当前索引内核不支持文件别名 / 评分」）。
