# 2026-11-03

## 蜗牛快搜（Rust + Tauri 2 + Vue 3 重写版）— 运行时验证与修复

项目：`E:\zbl\rust\rfile-workbuddy`，原型为 `E:\zbl\c++\SnailQuickSearch`（C++），搜索能力通过运行时加载闭源 `xunjieso.dll`（libloading + 197 个导出函数宏生成 `XjsApi`）。

### 本轮做的工作

1. **URL 协议（snailsearch://）补全**
   - 新增 `src/url-protocol.ts`：解析三种动作（new/open、search/find、focus）、搜索参数（q/ms/mode/filter/scope）、
     窗口参数（view/skin/zoom/preview/sort+order/save/win/hotkey/settings/force）、文件动作（run/reveal/props）、
     模式管理（addmode/mtype/tpl/mdesc/priv/delmode/cleartags）、匹配开关，以及 `run=` 的硬拒名单（exe/bat/ps1/……）。
   - `App.vue` 的 `handleUrl` 重写为「先文件动作、再界面、最后搜索」，最后统一弹一条 `ElMessage.warning` 汇总被拒原因。
   - 多重搜索链（`ms=`）用 `chain` 状态提交，界面出现虚线「多重搜索链」横条，输入即回到普通搜索。
   - 冷启动链接改由 `PENDING_URL` 挂起 + `take_pending_url` 命令取走（原来用固定 1.2s 睡眠投递，会丢参数）。
   - 解析器有自检：`.workbuddy/verify/url-protocol.test.ts`，`node --experimental-strip-types` 跑，45 组断言。

2. **协议注册改为原生注册表 API**
   - 原来靠 `reg.exe`，会被外部命令策略拦、且写失败只报「拒绝访问」。
   - 改用 `windows::Win32::System::Registry`（RegCreateKeyExW/RegSetValueExW/RegDeleteTreeW），
     需在 Cargo.toml 加 `Win32_System_Registry` + `Win32_Security` 特性。补了 DefaultIcon。
   - 新增 `url_protocol_registered()`（读注册表真实状态）+ 配置 `integration.protocol`，
     启动时若已开启则按当前 exe 路径刷新（程序挪位置后不用手改注册表）。

3. **运行时发现并修复的 4 个真 bug**（mock 模式全部测不出来）
   - **缺少 `src-tauri/capabilities/default.json`**：Tauri 2 下所有核心权限被拒，
     `event.listen` 失败又被 `.catch(()=>{})` 吞掉 → **引擎事件永远收不到**；窗口拖拽/最大化/文件对话框也全废。
     已补 capabilities 并把 event 订阅失败改为 `console.error`。
   - **非管理员下建索引静默失败**：`xjs_db_ScanPath` 返回成功但遍历线程立即退出（错误只留在引擎线程）。
     已在 `engine::start_scan` 前置 `is_admin()` 判断，直接 emit `xjs:scan-failed`（含「错误码 53」字样，前端据此弹提权层）。
   - **boot 阶段事件早于前端订阅**：`IndexStats` 增加 `boot_done` / `needs_admin` / `notice` 三个字段，
     由前端每秒轮询状态时消费，彻底消除时序竞态。
   - **`MatchSettings` 用 `#[serde(rename="中文键")]`**：中文键泄漏到 config.json 和 IPC，
     前端读 `pinyin_initial` 得到 undefined → 搜索匹配开关全部显示关闭且改了不生效。
     改成 `#[serde(alias="中文键")]`（只在读取时兼容旧的配置），引擎 JSON 仍由 `match_json()` 手工拼中文键。

4. **配置写回 bug**：`state.get()` 返回克隆，`state.save()` 存的却是原配置 → `start_scan` 存的硬盘列表、
   `register_url_protocol` 存的开关全丢。新增 `AppState::update(f)` 就地改+落盘。

5. **其他**：`save_db` 增加空库保护（没建过索引时保存会产出不可加载的 203 字节残片，加载报 rc=6）；
   `last_error()` 接到「关于」页做诊断；删掉 3 个死函数；`match_settings_json` 相关字段清理。

### 验证方式（重要经验）

- WebView2 可以开 CDP：`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9334` 启动 exe，
  然后 `node` 脚本连 `http://127.0.0.1:9334/json/list` 截图 + `window.__TAURI_INTERNALS__.invoke(...)` 直接调命令。
  脚本：`.workbuddy/verify/app-live.mjs`、`perm-test.mjs`、`proto-toggle2.mjs`、`url-e2e.mjs` 等。
- **真实闭环测过 URL 协议**：`Start-Process "snailsearch://new?q=报告&filter=文档&view=dense"`
  → 单实例转发 → 搜索框=报告、筛选 chip=文档、cfg.view.mode=dense；`run=C:\Windows\notepad.exe` 被拒且 notepad 未启动。
- Vite 只监听 IPv6，`curl 127.0.0.1:1420` 会失败，要用 `localhost` / `[::1]`。
- Chrome 无头 CDP 的界面冒烟脚本 `.workbuddy/verify/ui-check.mjs`（14 张截图，console errors 必须为 none）。

6. **匹配设置键名（第二轮）**：`#[serde(rename="中文键")]` 会同时影响序列化 → config.json 与 IPC 都是中文键，
   前端按 `pinyin_initial` 读全是 undefined，界面上 8 个匹配开关显示关闭且改了不生效。改 `#[serde(alias=...)]`
   后 config.json 落盘为英文键，旧的中文键文件仍能读。

7. **AppState::update(f)**：`state.get()` 是克隆 → 之前 `start_scan` 存的硬盘列表、协议开关全丢。

8. **热键状态可视化**：`hotkey::hook_ok()` + `hotkey_hook_ok` 命令，关于页显示「双击 Ctrl 已就绪 /
   键盘钩子未装上（可能被安全软件拦截）」。实测运行时返回 true，说明 WH_KEYBOARD_LL 装上了。

9. **发布构建**：`cargo build --release` 通过（2m20s），产物 4.1MB，二进制里能搜到
   `requireAdministrator` + `permonitorv2`（build.rs 只在非 debug 时注入清单）。
   注意：这个环境里 cargo 偶发卡死（rustc 只跑 1.6s CPU、23 分钟不动），杀掉重跑即可。
