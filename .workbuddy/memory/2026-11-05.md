# 2026-11-05

## 目录内浏览：分级排序 + 面包屑（tinker-search）

- 后端 `native.rs`：新增 `depth_under()` / `entry_group()`。进入目录（`scope` 非空）时
  在 `apply_sort()` 末尾用**稳定排序**再按组排一次：0 = 当前目录的子文件夹，
  1 = 当前目录的文件，2 = 更深层内容。组内仍是用户选的排序字段顺序（含降序）。
  `depth_under` 用 `path.get(..len)` 而不是切片，避免中文路径按字节切在字符中间；
  并且要求 `目录\` 边界，防止 `D:\ab` 把 `D:\abc` 误判成子项。
- 前端 `App.vue`：`crumbs` 由 `scope` 逐级拆分；结果区上方新增 `.crumbs` 导航条
  （首页按钮 + 每级可点 + 当前级 disabled + 右侧项数）。双击文件夹走 `enterFolder()`
  进入下一级，`goUpFolder()` 回到上一级，盘符根目录回到首页。
- 单测：`browse_order_tests` 用 `IndexBuilder` 造真实索引树，断言
  「文件夹 → 文件 → 更深层」以及组内顺序不被分组打乱。

## 快捷键：可自定义 + 只还原不隐藏

- `config.window.hotkey` 更名为 `shortcut`，默认 `DoubleCtrl`；旧的 `Alt+Space` 占位自动失效。
- `hotkey.rs` 支持两类绑定：双击修饰键（`DoubleCtrl`/`DoubleAlt`/`DoubleShift`/`DoubleWin`，
  也接受 `Ctrl+Ctrl`）与组合键（`Ctrl+Alt+S`、`Alt+Space`、`Win+Q`…，必须带修饰键）。
  低层钩子报告的是物理键 `0xA2/0xA3`，`modifier()` 统一认整个键族。
- 快捷键只调用 `show_main()`（还原 + 置前），**不再隐藏窗口**；关闭界面仍由
  `CloseRequested` 的 `window.hide()` 收进托盘。
- 窗口显隐一律走 tao 并在主线程按序执行（`show()` 必须先于 `unminimize()`）。
  根因：主窗口是 `decorations: false`，若只用原生 `SW_SHOW` 显示，tao 内部
  `WindowFlags::VISIBLE` 仍是 false，之后 `maximize()` 的 `apply_diff` 会补一刀
  `SW_HIDE` 并重设样式 —— 表现就是「恢复后点最大化，窗口连标题栏一起消失」。
  原生 Win32 只负责立即还原最小化与置前。
- 弃用 `AttachThreadInput`（会让系统静默摘掉低层键盘钩子），改 `SwitchToThisWindow` 兜底。

## 验证方式（本轮改用命令注入，不再截图）

- `cargo test --lib`：8 个单测全绿（热键绑定解析 3 + 目录层级/分组 5）。
- debug 版 + `TINKER_HOTKEY_TEST=1` 放行注入按键，用 `keybd_event` / `WM_CLOSE` /
  `WM_SYSCOMMAND` 直接驱动，Win32 读状态：
  - 关闭 → 隐藏（`vis=False`）；双击 Ctrl → 显示；再最大化 → `zoom=True, vis=True`，样式保留。
  - 外部最小化 → 双击 Ctrl → `iconic=False` 还原。
  - 连续多轮隐藏/唤出仍有效（钩子没有被摘）。
  - 配置改 `Ctrl+Alt+S` → 该组合可唤出，双击 Ctrl 失效（证明绑定真的跟随配置）。
- 注意：`Get-Process.MainWindowHandle` 在窗口隐藏后会指向别的窗口，验证脚本要按
  `class == "Tauri Window"` 枚举句柄。
- 后台窗口会反复抢前台，`GetForegroundWindow()` 观测到的 `fgIsApp=False` 不代表置前失败；
  外部单独调用 `SetForegroundWindow` 可成功，单实例唤起路径实测 `fgIsApp=True`。

  空闲 30–80µs，新文件 ≤250ms 可见，同步中查询中位 4.74ms。

- 对照：`walk C:/Windows` 395,430 条 / 58.2s = 0.68 万条/秒，MFT 枚举 17.2 万条/秒，差 25 倍。
