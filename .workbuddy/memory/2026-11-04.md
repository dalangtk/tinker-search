## 权限模型改造：主程序改为普通权限（asInvoker）

**动机**：原实现（清单 requireAdministrator + NSIS perMachine）导致双击就弹 UAC，
但实际只有「建库」需要管理员——原生头文件 `xunjieso.h:5` 写明"程序必须使用管理员权限或者服务运行"，
`xjs_db_ScanPath` 注释明确"需要管理员权限"（错误码 53），因为要解析 NTFS MFT / 读卷句柄；
遍历后的实时同步走 USN 日志，同样需要管理员。搜索、预览、图标、打开/定位/回收站、
剪贴板、托盘、双击 Ctrl 钩子、URL 协议注册（HKCU）全都不需要。

**另外发现**：原 C++ 项目 `SnailQuickSearch.exe.manifest` 用的是 `asInvoker`，
它是在启动时自己请求 UAC 重启（README 第 127 行），并不是清单硬性要求管理员。
原项目把 `xjs_db.dat` 放在 exe 同级（Program Files）→ 写入需要管理员；
我们把库放在 `%APPDATA%`，本就用户可写。

**改动**
- `build.rs`：清单 `requireAdministrator` → `asInvoker`，补 `longPathAware`。
- `tauri.conf.json`：NSIS `installMode` `perMachine` → `currentUser`（安装不再要 UAC）。
- `engine.rs::boot_db`：无库且非管理员 → 不调 `start_scan`（引擎会返回成功但线程静默退出），
  直接置 `NEED_ADMIN` + notice，搜索功能不受影响；有库则照常加载（不看权限）。
- `IndexStats` 新增 `admin` 字段，前端据此显示「索引只读 / 建库需管理员」。
- `shell::relaunch_elevated(args)`：支持传参；提权时带 `--elevated --wait-pid <pid>`。
- `lib.rs`：带 `--elevated` 时**不注册单实例插件**；带 `--wait-pid` 时先
  `WaitForSingleObject` 等旧进程退出再建 WebView2。
- 前端：引导层文案改为"建库这一步需要管理员权限"+ 可关闭（`.ov-x`）；
  设置-关于页显示运行权限；状态栏非管理员且库已就绪时显示「索引只读」；
  标题栏徽标由「非管理员」改为仅"没索引 + 没权限"时显示「待建索引」。

**踩到的坑（重要）**
- 两个实例同时用同一份 WebView2 用户数据目录会直接失败：

  在 `tauri::app` 的 setup 阶段 panic。所以提权实例必须先等旧实例真正退出（+700ms 让子进程释放）。
- 用 bash `( ... &)` 后台起进程会在命令结束时被回收，验证长驻进程必须走受管后台任务。
- **`cargo build --release` 不等于可分发产物**：不带 CLI 注入的 `custom-protocol` 特性时，
  release 二进制仍会在运行时去连 `devUrl`（localhost:1420），断网/关 Vite 就是白页
  `ERR_CONNECTION_REFUSED`。正确打包必须 `npm run tauri:build`（自动 vite build + NSIS），
  产物 URL 为 `http://tauri.localhost/`。

## 路径拼装与 find_id 反编译结果（11:00）
- `FUN_180125670`（真正的拼路径）：
  - 深度上限 **500**（`local_208 < 500`）；父 id == **-1** 表示根，遇到即 break。
  - **从缓冲区尾部往前写**：`local_268 = cap-1` 起步，每次 `local_268 -= len` 后 memcpy 名字，
    再在 `iVar2` 处写 `0x5c`('\\')，最后返回 `base + local_268 + 1` 作为字符串起点，长度累加到 `*param_5`。
    不需要临时栈、不需要预扫描长度，这是它能做到零分配的关键。
  - 父指针就是数组下标：`parent = *(int*)(*(int*)(engine+0x734) + slot)`；记录数在 `engine+0xf0`。
  - 记录有效性：取到的记录首字段 `== -2` 即**墓碑**，视为不存在（`FUN_180131340` = `find_id` 同样判定）。
  - 没有版本号：所以重建索引后老 ID 会静默指向别的文件（与它自己文档里的警告一致）。
- 与我的实现差异：我用了 `Vec<&str>` 栈 + 正序拼 String；功能等价，热路径上可改成尾部倒写进复用缓冲。

  所以 xunjieso 宣称的 6ms/1200万 **不可能是全量扫描**，必须靠候选收窄（n-gram 位图 / 前缀排序数组）。

- 验证：真实应用（调试版 + `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9334`
  走受管后台任务，别用 `( & )`）+ CDP `Runtime.evaluate`。截图确认首页 3 张磁盘卡 / 34 个桌面图块 /
  各盘目录、标签叠加与单个清除、三组收起、SQL 表格（10 组、`SUM(Size)` 显示 420 MB）。
- **坑**：连上 CDP 后不要 `Page.navigate`，也不要 `PUT /json/new`——新标签页不受 Tauri 管理，
  `window.__TAURI_INTERNALS__` 是 undefined，会得出「应用白屏」的错误结论。只连应用自己那个 page 目标。

## SQL 结果可预览/可打开 + 启动窗口尺寸

**1. SQL 结果行要像普通结果一样能预览能双击打开**
- `sscore::sql::Table` 增 `ids: Vec<u32>`，与 `rows` 一一对应（`DISTINCT` 跳过的不入）；
  `native::table_json` 输出 `"行id": [...]`。前端 `sqlRowAt(i)` 用它 `api.row(id)` 反查完整记录。
- DLL 后端没有 `行id`，退回按结果里的 `Path/路径` 列拼一条最小 `Row`（`id = -1`）。
  因此 `onKeydown` 里原来的 `if (row.id < 0) return` 必须放宽成 `if (!row) return`，否���合成行永远打不开。
- `SqlTable.vue` 新增 `:selected` + `@select/@open/@menu`，行上绑 click/dblclick/contextmenu，
  选中行高亮，`selected` 变化时 `scrollIntoView({block:'nearest'})`。
- `PreviewPane` 的显示条件去掉 `!sqlMode`，`:row` 改成 `sqlMode ? sqlRow : previewRow`。
- `move()`/`onKeydown` 在 SQL 模式走 `sqlSel` 而非结果缓存的 `selected`。
- `loadSql()` 开头必须 `sqlSel=0; sqlRow=null`：否则新 SQL 的 `pickSqlRow(0)` 被守卫
  `if (sqlSel===i && sqlRow) return` 拦住，预览还停在上一轮的文件上。
- 表格列宽：`td` 的 `max-width` 在自动布局里对 table-cell 不生效，长路径会把后面几列顶出视口。
  改为内层 `<span class="cell">`（路径列 280px / 其它 150px，`title` 存全值）。
- 聚合结果没有行，不参与选中/预览，hint 也换成「结果由引擎 SQL 模式直接输出」。

**2. 启动窗口过大**
- 根因：`WindowEvent::Resized/Moved` 给的是**物理像素**，原代码直接存进 cfg，
  在 150% 缩放的屏上存成了 `4256×2687`；下次启动又当逻辑像素还原 → 窗口超出屏幕，只露一角。
- 存的时候 `to_logical(scale_factor)`；读的时候 `restore_geometry()` 夹到工作区 92%，
  超过就判定脏数据回默认 `980×620` 并居中，同时把纠正值 `state.save()` 落盘（免得每次启动都纠）。
- 默认值三处一起改：`config.rs::WindowCfg::default`、`tauri.conf.json`、`restore_geometry` 的常量。

- 验证：CDP 里 `window.innerWidth/innerHeight` = 980×620；SQL 双击第 3 行后 Edge 窗口标题变成
  `876350034069.pdf …`，证明确实拉起系统默认程序（`invoke` 属性不可 `defineProperty`，没法从 IPC 层拦截，
  只能靠真实副作用判断）。

## 双击 Ctrl 热键 + 窗口显隐/置前重写（src-tauri/src/hotkey.rs）

- **真机上热键完全失灵的根因**：`WH_KEYBOARD_LL` 报物理键 `VK_LCONTROL(0xA2)` /
  `VK_RCONTROL(0xA3)`，原代码只匹配通用 `VK_CONTROL(0x11)`，用户按左右 Ctrl 永不触发。
  改为识别 `0x11 | 0xA2 | 0xA3`。
- **窗口操作全部 Win32 同步化**：tao 的 `unminimize/show/hide/set_focus` 只是往主线程
  PostMessage，调用方却可能是托盘/单实例/热键动作等不同线程，异步任务与陈旧窗口标志
  互相抵消 → 「按了没反应」「刚恢复又缩回去」。`show_and_foreground(hwnd)` 直接
  `IsIconic→SW_RESTORE`、`!IsWindowVisible→SW_SHOW`、`BringWindowToTop` +
  `SetForegroundWindow` + `SwitchToThisWindow` 兜底；隐藏走 `SW_HIDE`。
  启动时 `lib.rs` 也调 `bring_to_front`，避免前台锁把窗口留在别的程序后面。
- **显隐判断不依赖键盘焦点**：新增 `SHOWN` 原子状态，
  `should_hide(visible, minimized, shown)`。用 `GetForegroundWindow()==hwnd` 会被输入法/
  别的程序抢焦点，导致「再按一次收起」时灵时不灵。
- **坑**：`AttachThreadInput` 绕前台锁会扰动输入队列，实测系统静默摘掉低层键盘钩子
  （补挂也只多撑一次）→ 禁用，改用 `SwitchToThisWindow`。另留
  `WM_APP_REINSTALL_HOOK` + `HOOK_TID`，每次置前后 `PostThreadMessageW` 请钩子线程
  补挂，兜住杀软/超时导致的静默失效。
- **验证**：`cargo test --lib hotkey` 2/2、`vue-tsc --noEmit` 0 错误；debug 版
  `XJS_HOTKEY_TEST=1` 注入双击 Ctrl，连续 6 次正确交替显隐、隐藏后唤出、外部最小化后
  恢复（`.workbuddy/verify/hk-final.ps1`）；release 版启动置前、最小化后第二实例
  `iconic=False fg_self=True`、GUI 子系统无控制台、UI 完整。
- **测试环境限制**：`PostMessage(tray, 6002, ...)` 模拟托盘点击不可靠（tray-icon 先要
  `get_tray_rect`，拿不到就丢事件）；低完整性进程注入的按键在应用占着前台时会被 UIPI
  拦掉，需先把焦点挪开再注入。这两者都不是产品缺陷。
- 产物：`src-tauri/target/release/bundle/nsis/蜗牛快搜_1.0.0_x64-setup.exe`（3.46 MiB）。
